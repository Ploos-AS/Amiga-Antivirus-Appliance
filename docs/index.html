Preservation-oriented Amiga malware analysis

AAA — Amiga AntiVirus Appliance

AAA is an open-source appliance for scanning Commodore Amiga software, archives, disk images, and physically acquired floppy media while preserving evidence and attribution.

The reference appliance targets Orange Pi Zero 3 + DietPi (ARM64). The core scanner is portable and is continuously built for amd64 and arm64.

Core software is actively code-qualified; reference-hardware runtime qualification remains a separate gate.

What AAA does

Amiga-aware scanning

ADF bootblocks, OFS/FFS filesystems, reconstructed files, Amiga Hunk executables, exact hashes, provenance, and qualified signatures.

Archive pipeline

Bounded handling for ADZ, ZIP, LHA/LZH, LZX and DMS, including nested member scanning under shared safety budgets.

Preservation formats

Optional helper boundaries for IPF and FDI while retaining the original preservation image as primary evidence.

Multiple engines

Native AAA analysis, ClamAV integration, and isolated historical Amiga antivirus adapters with explicit engine/version attribution.

Appliance workflow

Daemon, persistent scan history, REST API, embedded Web UI, secure SMB drop-folder ingest, immutable staging, and restart-safe receipts.

Physical media

Greaseweazle acquisition workflows for ADF, multi-read repeatability, and raw SCP flux preservation without confusing acquisition evidence with malware evidence.

Evidence-first architecture

physical media / uploaded image / SMB drop → immutable or preservation-oriented acquisition → SHA-256 + provenance → format-aware static analysis → attributed scanner-engine evidence → persistent result/history → reviewable signature candidates

AAA deliberately separates acquisition evidence, scanner evidence, and malware verdicts. A different disk read, a malformed archive, or a preservation-format variation is not automatically malware.

Help improve Amiga malware detection: submit historical samples through AmiGuard.

AAA and AmiGuard share the same need for authentic historical Amiga virus and trojan material. Rather than creating competing sample channels, AAA directs community submissions to the AmiGuard sample project.

Do not attach suspected malware to GitHub issues, pull requests, discussions, or repository commits. The AmiGuard page documents the current submission status and safe preparation guidance.

What samples are useful?

Authentic historical bootblock viruses, infected Amiga executables, file/link viruses, trojans, suspicious disk images, old private collections, and recovered media can all be valuable when provenance is known or can be reconstructed.

Please preserve suspected samples unchanged and do not execute them merely to identify them. If possible, retain original filenames, disk/image format, approximate date, source, contemporary antivirus verdicts, notes, and SHA-256 hashes.

Supported workflow highlights

  • classic ADF geometry and bootblock analysis;
  • OFS/FFS traversal and file payload reconstruction;
  • Amiga Hunk structural analysis;
  • bounded archive and compressed-image decoding;
  • Signature Factory with review/promotion and ClamAV export;
  • historical scanner consensus/evidence architecture;
  • daemon, REST API, Web UI and persistent scan history;
  • secure authenticated SMB drop-folder workflow;
  • Greaseweazle ADF acquisition, repeatability comparison and raw SCP flux preservation.

Project status

AAA has progressed through the scanner, signature, daemon, Web UI, SMB ingest and early Greaseweazle acquisition milestones. Some features are code-qualified with deterministic CI fixtures while real Orange Pi Zero 3, Samba, emulator, preservation-decoder and physical-media runtime qualification remains intentionally separate.

Related project: AmiGuard

AmiGuard is the classic-Amiga antivirus project and community sample effort. AAA can consume compatible qualified signature outputs while adding appliance, preservation, multi-engine and physical-media workflows around the scanning process.
